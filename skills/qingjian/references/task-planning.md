# 整理与规划

## 整理入笺

提取目标、已完成证据、剩余节点和待决策事项。已有目标只整理，不擅自重新设计方法。只问缺失且影响结果的问题：关联哪个项目、记录今天部分还是整个阶段、截止/提醒是否需要。

用简短预览展示主标题、子标题、已完成/当前状态、日期及必要提醒。明确哪些是建议，确认后按 MCP 操作指南创建或更新。历史已完成节点仅在用户选择保留时加入，不自动扩展历史。

## 拆解与每日规划

从用户已给信息开始；缺少时询问主要成果、实际可用时间、固定安排、截止约束。不要求填完整问卷。控制当天任务量，保留机动空间。若超负荷，提出取舍，不擅自取消。

跨日计划根据父子同日约束按日期/阶段拆主任务，先让用户看组织方式。未选择写入时仅交付计划，不调用写工具。

## 节点粒度

让节点描述可核对的结果，如“核查异常簇注释”，不用“处理一下”。将代码实现、计算执行、结果核查分别表达，避免进度虚高。多日大项目分阶段，勿每个函数一个条目。

## 例子

用户在讨论分析时说“把这个加入轻笺”：从实际上下文生成“完成本轮分析与核查”及确定步骤；未决定的回归变量写成“确认回归方案”，不擅自替用户选方法。预览并确认后创建。

用户说“下午临时有事，重排”：读取完成情况，讨论保留/顺延，确认新日期后更新原 ID，不重新生成整套任务。
